# 防过拟合检查清单

## 过拟合信号

### 信号1：上下文绑定
- [ ] Skill中的步骤是否依赖特定项目/产品/工具名称？
- [ ] 是否存在仅适用于特定时间/地点的假设？
- [ ] 替换主体后方法是否仍然有效？

### 信号2：粒度失衡
- [ ] 步骤是否过于具体到无法复用？
- [ ] 步骤是否过于笼统以至于无指导价值？
- [ ] 工作流是否在5-15步之间？

### 信号3：重复造轮子
- [ ] 与现有Skill的功能重叠度是否超过50%？
- [ ] 是否可以扩展现有Skill而非新建？
- [ ] 触发条件是否与现有Skill难以区分？

### 信号4：隐性知识
- [ ] 是否存在未言明的假设？
- [ ] 步骤是否隐含了需要外部知识的前提？
- [ ] 非领域专家是否能按步骤执行？

## 通用性检验

### 替换测试
将Skill中的特定名词替换为通用名词，检查方法是否仍然成立：
```
原文: "使用Kimi的搜索工具查找..."
替换: "使用搜索工具查找..."
结果: 方法仍然成立 → 通过
```

### 场景扩展测试
列举至少3个不同场景，检查Skill是否都能适用：
```
场景1: [领域A的类似问题] → 是否适用？
场景2: [领域B的类似问题] → 是否适用？
场景3: [规模不同的类似问题] → 是否适用？
```

### 最小可用测试
Skill是否包含足够的约束和检查点，使得执行者不会走偏？

## 修正策略
| 问题 | 修正方法 |
|------|---------|
| 上下文绑定 | 抽象为通用参数 |
| 粒度过细 | 合并为通用步骤，细节放入references |
| 与现有Skill重复 | 评估扩展vs新建，明确差异 |
| 隐性知识 | 显式声明前提条件和输入要求 |
