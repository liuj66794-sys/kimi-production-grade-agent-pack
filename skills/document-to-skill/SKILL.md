# Document-to-Skill Skill

## 目的
将高质量参考文档、经验总结、方法论沉淀转化为结构化的、可复用的Skill定义。

## 触发条件
- 现有Skill需要基于新文档增强时
- 发现可复用的方法论需要固化为Skill时
- 文档分析任务中识别出模式需要沉淀时
- 已有文档需要转化为可调用Skill格式时

## 输入
- 高质量的参考文档或经验文档
- 目标Skill的定位和范围
- 相关现有Skill（避免重复）

## 输出
- 结构化Skill定义（含frontmatter、工作流、边界）
- references/目录下的支持文档
- 与现有Skill的区分说明
- 适用场景示例

## 工作流
1. **文档分析**：
   - 阅读并理解参考文档的核心方法论
   - 识别可复用的模式、框架、清单
   - 提取触发条件和决策规则
2. **模式提取**：
   - 将具体案例转化为通用规则
   - 保留可操作的步骤和检查项
   - 去除特定上下文依赖
3. **结构化转化**：
   - 编写YAML frontmatter
   - 定义触发条件
   - 编写工作流（步骤清晰、可执行）
   - 定义输出契约
   - 列出Hard Fail条件
4. **边界定义**：
   - 明确适用范围
   - 明确不适用场景
   - 定义与相邻Skill的关系
5. **防过拟合检查**（参考 overfitting-check.md）：
   - 检查是否过度绑定特定文档上下文
   - 验证通用性
   - 检查与现有Skill的重复度
6. **输出Skill文件**：
   - 生成SKILL.md
   - 生成references/下的支持文档

## Hard Fail条件
1. 直接复制粘贴文档内容而非提取模式
2. 未定义明确的触发条件
3. Skill范围过于宽泛（什么都做）或过于狭窄（仅适用一个场景）
4. 与现有Skill重复而不做区分
5. 未包含输出契约或边界定义

## 不负责
- 不替代原始文档的详细内容（Skill是控制面，不是知识库）
- 不做文档质量评估（假设输入为高质量文档）
- 不维护非Skill格式的知识库

## 输出契约
- 生成的Skill必须包含完整frontmatter
- 必须包含触发条件、工作流、输出契约、边界
- references/目录必须包含至少一个支持文档
- 必须说明与现有Skill的差异
