# 质量审查检查清单 v1.2

> **v1.2适用范围**: 本checklist适用于L1主链路全部产物的质量审查，
> 包括: task-intake输出、researcher-result、analyst-result、
> evidence-map、draft-report、final-report、artifact-manifest。
>
> **集成门禁规则**: QA fail后不得进入eval-runner。qa-reviewer输出fail时，
> 必须阻止final-report.md生成，只能生成fix-required.md。

---

## 审查维度总览（9个维度）

| # | 维度 | 关键问题 | 权重 |
|---|------|---------|------|
| 1 | 事实来源可靠性 | 每个事实是否有可靠来源支撑？ | 高 |
| 2 | 逻辑推理严谨性 | 推理链条是否完整、无逻辑漏洞？ | 高 |
| 3 | 不确定性说明完整性 | 所有不确定性是否诚实标注？ | 高 |
| 4 | 格式统一性 | 是否符合模板和格式规范？ | 中 |
| 5 | 代码测试验证 | 代码是否可运行、测试结果是否真实？ | 高 |
| 6 | 表格可追溯性 | 表格数据是否可追溯到来源？ | 中 |
| 7 | PPT页级观点 | 每页是否有明确的核心观点？ | 中 |
| 8 | 文件命名清晰 | 文件名是否清晰反映内容？ | 低 |
| 9 | 最终产物可用性 | 产物是否满足交付要求？ | 高 |

## 维度1：事实来源可靠性

### 检查项

- [ ] **F1.1** 每个核心事实都有至少一个来源引用
- [ ] **F1.2** 引用来源质量符合最低要求（Fact: 1个A级或2个B级）
- [ ] **F1.3** 来源引用可追溯到原始出处（非转引无标注）
- [ ] **F1.4** 不存在编造来源或虚构引用
- [ ] **F1.5** 数值、日期、名称等具体数据有明确来源
- [ ] **F1.6** 不存在将间接引用包装成直接引用的情况
- [ ] **F1.7** 引用内容与原始来源一致，无断章取义
- [ ] **F1.8** 存在冲突的数据/观点已被识别和处理

### 通过标准

| 结果 | 条件 |
|------|------|
| **pass** | F1.1-F1.8全部通过 |
| **warn** | F1.1-F1.5通过，F1.6-F1.8中有1-2项存在minor问题 |
| **fail** | F1.1-F1.5中任意一项未通过，或存在编造来源(F1.4) |

### 审查方法
1. 随机抽取30%的Claim，检查引用完整性
2. 对High-impact Claim（涉及决策建议）100%检查
3. 验证引用编号与来源清单的对应关系

---

## 维度2：逻辑推理严谨性

### 检查项

- [ ] **F2.1** 推理链条完整，每个中间步骤都有支撑
- [ ] **F2.2** 前提与结论之间有合理的逻辑联系
- [ ] **F2.3** 不存在循环论证
- [ ] **F2.4** 不存在偷换概念或歧义定义
- [ ] **F2.5** Inference类Claim展示了完整的推理路径
- [ ] **F2.6** 充分性假设已声明（样本是否有代表性、时间范围是否充分）
- [ ] **F2.7** 不存在从"是"到"应该是"的无授权跳跃
- [ ] **F2.8** 类比推理（如有）具有合理的相似性基础

### 通过标准

| 结果 | 条件 |
|------|------|
| **pass** | F2.1-F2.8全部通过 |
| **warn** | F2.1-F2.5通过，F2.6-F2.8存在minor问题 |
| **fail** | F2.1-F2.5中任意一项存在严重逻辑漏洞，或存在循环论证(F2.3) |

### 审查方法
1. 对每个Inference Claim，追溯其推理路径
2. 检查是否存在未声明的前提假设
3. 检查是否存在因果推断过度

## 综合判定规则

### pass / fail / pass_with_notes 判定

```
最终判定:
├─ 维度1-3（高权重维度）全部pass
│   ├─ 且维度4-9全部pass → pass
│   ├─ 且维度4-9有warn但无fail → pass_with_notes
│   └─ 且维度4-9任意fail → fail（需看具体fail项）
├─ 维度1-3有任意warn → pass_with_notes（至少）
├─ 维度1-3有任意fail → fail
└─ 触碰安全红线 → 强制fail，必须修正
```

### 详细判定矩阵

| 高权重(1-3) | 中低权重(4-9) | 最终结果 |
|------------|--------------|---------|
| 全部pass | 全部pass | **pass** |
| 全部pass | 有warn无fail | **pass_with_notes** |
| 全部pass | 有fail | **fail**（需修正后重审） |
| 有warn | 全部pass | **pass_with_notes** |
| 有warn | 有warn | **pass_with_notes** |
| 有warn | 有fail | **fail** |
| 有fail | 任意 | **fail** |

### 安全红线（触碰即强制fail）

以下任一情况出现时，无论其他维度如何，强制判定为**fail**：

- **R1**: 存在编造来源或虚构引用
- **R2**: 存在事实性错误（与可靠来源矛盾）
- **R3**: 隐藏已知冲突信息
- **R4**: 新增未经evidence-synthesis支撑的结论
- **R5**: 泄露敏感信息或内部模块名
- **R6**: QA fail但仍生成final-report.md
- **R7**: 工具失败后假装成功
- **R8**: 伪造测试结果（声称pass但无实际运行记录）

## v1.2新增审查项

### artifact-manifest校验

在维度9（最终产物可用性）中新增以下检查：

- [ ] artifact-manifest.json文件存在
- [ ] manifest中所有`required: true`的artifact都存在
- [ ] artifact路径指向项目内路径（非外部路径）
- [ ] 每个artifact都有producer标注
- [ ] final-report.md不在QA fail后生成

### task-events完整性校验

在维度9中新增以下检查：

- [ ] task-events JSONL文件存在且可解析
- [ ] 包含`task_created`事件
- [ ] 包含`subtask_done`事件（每个子任务）
- [ ] 包含`quality_review_started`和`quality_review_done`事件
- [ ] 包含`task_completed`或`task_failed`事件之一
- [ ] 不存在`task_completed`和`task_failed`同时出现
- [ ] 事件时序合理（started在done之前）
