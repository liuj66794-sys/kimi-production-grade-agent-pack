# v4.3 Context Management Specification

## 概述

Context Pack Compiler 管理三层上下文系统（热/温/冷），确保在 token 预算限制内提供最优上下文，同时保护安全配置不被截断。

---

## 三层架构

### 热层 (Hot Context) ~16K tokens

包含当前对话中最关键的上下文：
- 当前对话历史
- 活跃任务状态
- 当前 Autonomy Policy 摘要
- Pending Approvals 摘要
- Anomaly Counter 当前值

### 温层 (Warm Context) ~32K tokens

包含近期相关的历史信息：
- 近期任务历史
- 相关记忆条目
- 路线图摘要
- 项目状态摘要

### 冷层 (Cold References)

仅存储引用，不直接加载：
- 完整项目历史
- 归档的任务事件
- 旧版本的产物
- 外部存储的大型文件

---

## Protected Keys

以下 key 在 context pack 截断时必须保护，**不可被截断**：

- `autonomy_policy` - 自治策略
- `hitl_config` - HITL 配置
- `security_rules` - 安全规则
- `pending_approvals` - 待审批列表
- `anomaly_counter` - 异常计数器

Protected keys 占用 token 预算，在极端情况下可能接近 50KB（参见 KL-L4-001）。

---

## Context Pack 编译流程

```
1. 收集热层上下文
   |
2. 计算热层已用 tokens
   |
3. 如有剩余预算，按相关性选择温层条目
   |
4. 标记冷层引用（不直接加载）
   |
5. 确保 protected keys 完整保留
   |
6. 如总 token 超出预算，优先截断温层
   |
7. 如仍超出，截断热层中非 protected 部分
   |
8. 输出编译后的 context pack
```

---

## Token Budget 管理

| 层级 | 限制 | 优先级 |
|------|------|--------|
| max_tokens | 128000 | 硬限制 |
| hot_context_limit | 16000 | 软限制（优先保证） |
| warm_context_limit | 32000 | 软限制 |
| protected_keys | 不限制单独预算 | 最高优先级 |

### 截断顺序

1. 首先保证 protected keys 完整
2. 其次保证热层核心内容
3. 然后填充温层
4. 超出时先截断温层低相关性条目
5. 最后截断热层非 protected 内容

## Context Pack 输出格式

```json
{
  "version": 1,
  "total_tokens": 45230,
  "hot_context": "string (热层上下文内容)",
  "warm_context": "string (温层上下文内容)",
  "cold_references": [
    "path/to/old/task-events.json",
    "path/to/archived/artifact.json"
  ],
  "protected_keys": [
    "autonomy_policy",
    "hitl_config",
    "security_rules",
    "pending_approvals",
    "anomaly_counter"
  ],
  "truncation_log": [
    {
      "layer": "warm",
      "reason": "token_budget_exceeded",
      "items_removed": 5,
      "timestamp": "2026-04-25T00:00:00Z"
    }
  ]
}
```

## 相关性评分

温层条目按以下因素排序：

1. 时间临近性（越近越相关）
2. 任务关联性（与当前任务的关联度）
3. 访问频率（最近被引用的次数）
4. 优先级标签（高优先级优先）

---

## 安全约束

1. Protected keys 在任何情况下都不可被截断
2. 截断操作必须记录 truncation_log
3. Context pack 超出 max_tokens 时必须 hard fail
4. Autonomy Policy 摘要在热层必须保留
