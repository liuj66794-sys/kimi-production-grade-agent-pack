# Kimi Production-Grade Agent Pack v1.1 - Technical Specification

## 1. 概述

本文档定义 Kimi Production-Grade Agent Pack v1.1 技术预研阶段的完整文件级规格，涵盖 P0-pre 预验证、P0 核心验证、评测执行器骨架、硬失败检测骨架、单元冒烟测试卡片、结构化输出策略、执行器状态机、手动执行器、运行时依赖解析和调试日志规格。

## 3. 各文件详细规格

### 3.1 scripts/p0_pre_sdk_test.py

**通过标准详细说明**:
- 连续运行3次，至少2次成功返回（`successful_runs >= 2`）
- 成功返回的latency均 `< 30s`
- 3次运行的中位数latency `< 20s`
- 任何单次latency `> 60s` 视为异常，记录但不阻断测试
- 成功返回的输出必须能被 `json.loads()` 解析
- 解析后 `status == "ok"`

**输出文件格式**:
```
evals/results/p0-pre/sdk-headless/
├── run-001-output.json       # 解析后的JSON输出
├── run-001-raw.txt           # 原始文本输出
├── run-001-reasoning.txt     # 推理过程（不可用占位）
├── run-002-output.json
├── run-002-raw.txt
├── run-003-output.json
├── run-003-raw.txt
├── errors.jsonl              # 错误信封JSONL
├── debug.log                 # 时间戳调试日志
└── result.json               # 聚合结果
```

**result.json 完整字段**:
```json
{
  "p0_pre_001": "PASS|SKIP|FAIL",
  "runner": "sdk|cli|manual|none",
  "runs": 3,
  "successful_runs": 0..3,
  "passed_runs": 0..3,
  "median_latency_seconds": 11.2,
  "max_latency_seconds": 18.4,
  "latency_anomaly": false,
  "json_parse_success": true,
  "reasoning_content": "unavailable",
  "fallback_used": null,
  "sdk_available": true,
  "sdk_version": "1.0.0",
  "cli_available": true,
  "cli_version": "0.9.1",
  "total_duration_seconds": 45.6,
  "run_details": [...]
}
```

### 3.2 scripts/p0_pre_runtime_write_test.py

**测试流程**:
1. 生成3条带时间戳的JSONL记录
2. 写入 `runtime/test-write.jsonl`
3. 追加1条额外记录测试append-only
4. 读取并逐行解析验证
5. 计算MD5校验

**通过标准详细说明**:
1. 创建 `runtime/test-write.jsonl`（或fallback路径）
2. 连续追加写入3条JSONL记录
3. 每条记录可被 `json.loads()` 解析
4. 文件MD5与预期内容一致
5. 读取时无权限错误

**输出文件格式**:
```
runtime/
└── test-write.jsonl
evals/results/p0-pre/runtime-write/
├── result.json
├── errors.jsonl
├── debug.log
└── fallback.jsonl          # 仅当使用fallback时生成
```

### 3.3 schemas/error-envelope.schema.json

**验证规则**:
- 所有 `required` 字段必须存在
- `layer` 必须为枚举值之一: `plugin`, `mcp`, `script`, `skill`, `flow`, `subagent`, `coordinator`
- `severity` 必须为枚举值之一: `info`, `warning`, `recoverable`, `fatal`
- `recoverable` 和 `retryable` 为布尔值
- `additionalProperties: false` 表示不允许额外字段

**使用场景**:
- SDK timeout → `layer: "script"`, `severity: "recoverable"`, `fallback_action: "cli"`
- 目录创建失败 → `layer: "script"`, `severity: "fatal"`, `fallback_action: null`
- JSON解析失败 → `layer: "script"`, `severity: "warning"`, `fallback_action: null`

| `runner_fallback_chain` | array | 是 | fallback链路数组 |
| `sdk_available` | boolean | 是 | SDK是否可用 |
| `cli_available` | boolean | 是 | CLI是否可用 |
| `sdk_version` | string\|null | 是 | SDK版本号 |
| `cli_version` | string\|null | 是 | CLI版本号 |
| `model_name` | string | 是 | 模型名称 |
| `pack_version` | string | 是 | Pack版本 |
| `start_time` | string | 是 | 开始时间 ISO-8601 |
| `end_time` | string | 是 | 结束时间 ISO-8601 |
| `total_latency_seconds` | number | 是 | 总耗时秒数 |
| `cases_run` | number | 是 | 运行case数 |
| `cases_passed` | number | 是 | 通过case数 |
| `cases_failed` | number | 是 | 失败case数 |
| `notes` | string | 是 | 备注 |

### 3.5 evals/runner/eval_runner.py

**核心职责**:
- 加载所有P0测试case
- 根据runner类型(sdk/cli/manual)执行测试
- 管理runner fallback链路
- 生成每个case的结果文件
- 汇总生成run-metadata

**启动参数**:
```powershell
python evals/runner/eval_runner.py \
  --pack-dir ./ \
  --runner auto \
  --cases "p0_*" \
  --output-dir evals/results/```

---

### 3.6 evals/runner/check_hard_fail.py

**检测标准**:
- 扫描所有 `result.json` 中的 `FAIL` 状态
- 扫描 `errors.jsonl` 中的 `fatal` severity错误
- 检查关键文件缺失
- 输出 `hard-fail-report.json`

**报告格式**:
```json
{
  "has_hard_fail": true,
  "failed_cases": ["p0_pre_001"],
  "fatal_errors": [...],
  "recommendation": "manual-smoke-required"
}
```

### 3.9 evals/runner/state_machine.py

**状态定义**:
```
IDLE → INITIALIZING → DETECTING_RUNNER → RUNNING_CASES →
  → GENERATING_REPORT → COMPLETED
                    ↘ HARD_FAIL_DETECTED → ABORTED
                    ↘ MANUAL_REQUIRED → WAITING_INPUT
```

**功能**:
- 提供手动执行模板生成

**功能**:
- 解析 `requirements.txt` 和 `pyproject.toml`

### 3.12 docs/debug_log_spec.md

**日志格式规范**:
```
[ISO-8601-timestamp] [LEVEL] message
```

**日志级别**: `DEBUG`, `INFO`, `WARNING`, `ERROR`, `FATAL`
