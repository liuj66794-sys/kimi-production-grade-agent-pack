# v2.5 L2 Release Specification

## Overview

This document defines the release criteria and validation procedures for the L2
capability layer of the Kimi Production-Grade Agent Pack. It specifies the
checklist, automated scripts, and gating criteria for promoting L2 from
development to production.

## Release Checklist

### 1. L1 Integrity Verification
- [ ] All L1 agent configurations remain unchanged
- [ ] All L1 skills function correctly
- [ ] L1 regression suite passes 100%
- [ ] No L1 tool permissions modified
- [ ] Orchestrator routing logic verified

### 2. L2 Agent Configuration
- [ ] Each L2 agent YAML is valid and parseable
- [ ] Tool permissions follow whitelist/denylist model
- [ ] Hard-fail rules are defined for each agent
- [ ] Schema enforcement configured
- [ ] Degradation strategies documented

### 3. L2 Skill Validation
- [ ] Each SKILL.md has valid YAML frontmatter
- [ ] Trigger conditions are specific and unambiguous
- [ ] Capability ranges are well-defined
- [ ] Hard-fail rules are actionable
- [ ] Output schemas specified

### 4. Schema Validation
- [ ] All JSON schemas are Draft 7 compliant
- [ ] Schemas validate against example outputs
- [ ] Required fields are minimal and correct
- [ ] Type definitions are strict

### 5. Script Verification
- [ ] `l2_spike_runner.py` executes all spikes
- [ ] `l2_regression_runner.py` runs L1+L2 suites
- [ ] `l2_release_check.py` validates release readiness
- [ ] All scripts have error handling and logging

### 6. Memory Safety
- [ ] Memory module is NOT enabled in production release
- [ ] Memory agent exists but is gated behind feature flag
- [ ] No persistent storage activated without explicit opt-in
- [ ] Session isolation verified

### 7. Documentation
- [ ] All spec documents (v2.0 through v2.5) are complete
- [ ] Risk review document is up-to-date
- [ ] Known limits documented
- [ ] Runtime SLA published

## Release Gates

### Gate 1: Pre-Merge Checks (Automated)
```powershell
# Run before any merge to main
python scripts/l2_release_check.py --pre-merge```
- Validates YAML syntax for all agents
- Validates JSON schemas
- Checks file completeness (all 31 files present)
- Runs unit smoke tests

### Gate 2: Spike Validation (Automated)
```powershell
# Run after each spike completion
python scripts/l2_spike_runner.py --spike all```
- Executes each spike's test suite
- Validates agent-tool permission bindings
- Checks skill trigger conditions
- Reports pass/fail per spike

### Gate 3: Regression Testing (Automated)
```powershell
# Run before release candidate
python scripts/l2_regression_runner.py --suite full```
- Runs L1 regression suite (100% must pass)
- Runs L2 unit smoke tests (100% must pass)
- Checks for cross-contamination between agents
- Validates schema compliance of all outputs

### Gate 4: Manual Review
- Security review of tool permissions
- Hard-fail rule coverage review
- Documentation completeness check
- Performance SLA verification

## Versioning

- **Pack version**: Follows semantic versioning (major.minor.patch)
- **Agent version**: Independent, follows same schema
- **Skill version**: Independent, tied to agent compatibility
- **Schema version**: Independent, backward-compatible within major version

## Rollback Plan

If critical issues discovered post-release:
1. Disable affected L2 agent via feature flag
2. Revert to L1-only mode
3. Fix and re-validate
4. Re-enable via patch release

## Post-Release Monitoring

- Track agent activation rates per L2 domain
- Monitor error rates against SLA thresholds
- Log hard-fail trigger frequency
- Collect schema validation failure rates
