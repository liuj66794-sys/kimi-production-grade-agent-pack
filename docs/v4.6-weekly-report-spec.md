# v4.6 Weekly Report Specification

## 概述

Weekly Report 生成器汇总过去 7 天的项目活动，包括任务完成情况、产物生成、异常检测和上下文预算使用。

---

## 数据源

1. **task-events**: 过去 7 天的任务事件日志
2. **project-state.json**: 当前项目状态
3. **roadmap.json**: 路线图状态
4. **pending_approvals**: 待审批列表
5. **audit log**: 审批和操作日志

---

## 报告结构

### 1. 本周概览

```
报告周期: YYYY-MM-DD ~ YYYY-MM-DD
项目状态: active | paused | degraded
Autonomy Level: a1 | a2 | a3 | a4 | a5
Sprint: sprint-001 (L4 Foundation)
```

### 2. 完成的任务

| 任务ID | 名称 | 状态 | 完成时间 |
|--------|------|------|----------|
| T-001  | 任务1 | completed | 2026-04-24 |

### 3. 生成的产物

| 产物 | 类型 | 路径 |
|------|------|------|
| artifact-1 | report | output/report.md |

### 4. 异常和 Blockers

- 异常事件列表
- 阻塞的任务
- Autonomy Gate block 统计

### 5. Pending Approvals

| 审批ID | 动作 | 级别 | 请求时间 | 状态 |
|--------|------|------|----------|------|
| apr-001 | update_task | a3 | 2026-04-24 | pending |

### 6. 建议的下一步

基于当前状态自动生成的建议。

### 7. Context Budget 使用情况

| 层级 | 使用 | 限制 | 使用率 |
|------|------|------|--------|
| Hot  | 12000 | 16000 | 75% |
| Warm | 28000 | 32000 | 87% |
| Total| 40000 | 128000 | 31% |

## 生成流程

```python
def generate_weekly_report() -> dict:
    """
    1. 读取过去7天的 task-events
    2. 统计完成/失败/阻塞的任务
    3. 汇总产物生成情况
    4. 列出 pending approvals
    5. 检测异常模式
    6. 统计 context budget 使用
    7. 生成 weekly-report.md
    8. 推荐下一步行动
    """
```

1. Weekly Report 生成是 A1 动作（只读）
2. 发布 Weekly Report 是 A3 动作（需 HITL 审批）
